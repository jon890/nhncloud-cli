# 복구 가이드가 실패 시점을 구분하지 않았다

## 관찰

공개 가이드의 이어받기 절이 `추출이 실패하면`으로 시작했다.
바로 아래에서 조회 완료 뒤 실패를 따로 설명하지만, 해당 문장만 읽으면 모든 실패가 `.partial`을 남기는 것으로 오해할 수 있었다.

## 원인

새 복구 상태를 별도 절에 추가하면서 기존 `.partial` 문장의 주어와 실패 시점을 함께 좁히지 않았다.

## 영향

사용자가 `.complete`나 `.unfinalized`를 보고도 API를 다시 호출하거나 이어받기를 시도할 수 있었다.

## 대응

`.partial` 설명을 조회가 끝나기 전 실패로 한정한다.

## 검증

공개 가이드의 문장을 `조회가 끝나기 전에 추출이 실패하면`으로 좁혔다.
code-reviewer가 누적 diff와 현재 수정 파일을 다시 읽고 `PASS`로 판정했다.

## 배운 점

실패 상태를 세분화할 때는 새 상태 설명만 추가하지 말고 기존 포괄 문장의 범위도 함께 좁혀야 한다.

## 후속

낮은 심각도의 한 번성 문구 누락이라 별도 반복 함정으로 승격하지 않는다.
