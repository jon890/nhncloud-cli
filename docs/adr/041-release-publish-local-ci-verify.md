# ADR-041: npm 게시는 로컬에서 사람이 하고, 태그 push 워크플로는 검증만 한다

- **status**: `accepted`
- **결정**: `v*` 태그 push 로 도는 `.github/workflows/release.yml` 은 공개 정보 검사, 타입 검사, 테스트, 빌드, 패키지 산출물 검증, 태그와 `package.json` 버전 일치, pre-release 거부만 수행한다.
  - npm 게시는 릴리스 스킬이 안내해 사용자가 로컬에서 실행한다. 에이전트는 게시 전 `npm publish --access public --dry-run` 결과를 보이고, 게시 뒤 registry 반영을 기다리며 확인한다.
  - 워크플로의 게시 단계는 저장소 변수 `NPM_TRUSTED_PUBLISHING` 이 `true` 일 때만 돈다. 기본은 꺼져 있다.
- **맥락**:
  - npm 계정의 2단계 인증이 쓰기에도 걸려 있어(`auth-and-writes`) 게시 때 브라우저 인증이 필요하다. 에이전트가 대신 실행할 수 없다.
  - Trusted Publishing(OIDC)은 저장소 secret 없이 CI 에서 게시하는 방법이다. 형제 프로젝트 dooray-cli 에서 2026-09 에 등록을 시도했을 때 registry 가 본문 없는 400 을 냈고 원인을 찾지 못했다. 이 저장소에서는 시도하지 않았다.
  - 게시 직후 `npm view` 는 이전 버전을 낸다. v0.18.0 에서는 반영까지 4분이 걸렸다.
- **대안 기각**:
  - 저장소 secret 에 npm 토큰을 두고 CI 에서 게시: 공개 저장소의 장기 토큰은 유출되면 패키지를 덮어쓸 수 있다. 2단계 인증을 쓰기에서 빼야 해 계정 보호도 약해진다.
  - 태그 워크플로 없이 로컬 검사만 유지: 로컬 환경과 CI 환경이 갈리는 문제(Node 버전, 빠진 파일)를 게시 직전에 잡지 못한다.
- **결과**:
  - 얻는 것: 태그를 밀면 게시할 커밋이 CI 와 같은 환경에서 검증된다. 버전이 어긋난 태그나 pre-release 가 `latest` 로 나가는 것을 막는다.
  - 감당할 것: 게시는 계속 사람이 해야 한다. Trusted Publishing 을 등록하면 변수를 켜고 이 ADR 의 게시 방식 결정을 다시 본다.
