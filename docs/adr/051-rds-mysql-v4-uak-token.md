# ADR-051: RDS for MySQL 은 API v4.0 과 UAK 토큰으로 호출하고, 응답 본문 없는 쓰기와 파괴적 쓰기를 따로 다룬다

- **status**: `accepted`. [[adr-046]] 의 API 버전(v3)과 인증(정적 헤더) 결정을 대체한다.
- **결정**:
  - `nhncloud rds-mysql` 은 RDS for MySQL API v4.0(`/v4.0`)을 호출한다. 기존 `instance`, `schema`, `user`, `job` 명령도 같은 클라이언트로 v4.0 을 쓴다.
  - 인증은 요청마다 `X-TC-APP-KEY`(profile `rds-mysql.appkey`)와 `X-NHN-AUTHORIZATION: Bearer <UAK 토큰>` 을 보낸다. 토큰은 다른 OAuth 서비스와 같은 `src/api/oauth.ts` 의 `getAccessToken` 과 `user-access-token-<profile>` 캐시를 쓴다([[adr-007]]).
  - host, region 옵션, 응답 봉투 판정, 결과 코드와 종료 코드 규칙은 [[adr-046]] 을 그대로 따른다.
  - 쓰기는 [[adr-047]] 의 미리보기와 `--wait` 규칙을 따른다. 아래를 더한다.
    - 응답에 작업(`jobId`)이 없는 쓰기(파라미터 그룹 복사·값 변경·초기화, 바이너리 로그 삭제)는 `--wait` 를 두지 않는다. 요청이 접수되면 반영된 것으로 보고 해당 조회 명령으로 확인하라고 안내한다. 이런 요청은 빈 응답 본문도 성공으로 받는다.
    - 파라미터 값 변경은 파라미터 그룹의 값만 바꾼다. 연결된 DB 인스턴스에는 적용되지 않고 그룹이 `NEED_TO_APPLY` 가 된다. 적용은 콘솔의 유지 관리(「파라미터 그룹 변경 사항 적용」)가 하고, 재시작이 필요한 파라미터를 적용할 때 DB 인스턴스가 재시작된다.
    - 파라미터 적용 유형 `FILE` 은 재시작 필요, `BOTH` 는 동적, `SESSION` 은 세션 단위로 풀어 보인다. API 는 이 뜻을 밝히지 않고 콘솔 가이드의 「고정은 재시작, 동적은 바로 적용」 과 이어 읽은 것이라 출력에 「추정」 을 붙인다.
    - 바이너리 로그 삭제는 `--before <파일>` 로 그 파일을 남기고 직전까지 지운다. 미리보기에 지울 파일 수와 크기 합을 보이고 특정 시점 복원이 안 될 수 있다고 경고한다.
    - 스토리지는 늘리기만 한다. 현재보다 작은 값은 요청 전에 종료 코드 3 이다. 자동 확장을 쓰고 있으면 현재 설정을 함께 보내 끄지 않는다.
    - 재구축은 `FAILED_MASTER`, `CANDIDATE_MASTER`, `READ_ONLY_SLAVE` 에만 한다. 정상 Primary(`MASTER`)는 요청 전에 종료 코드 3 이다. 재구축은 대상의 모든 데이터베이스를 지우고 Primary 에서 다시 만든다.
- **맥락**:
  - 바이너리 로그 목록·삭제, 고가용성 조회, 재구축, 백업 단건 조회는 v3.0 문서에 없고 v4.0 에만 있다. 이 API 들이 필요해서 버전을 올린다. 일반망과 공공망 v4.0 문서의 경로는 97개로 같고, 공공망 문서에는 판교(`kr1`) host 하나만 있다.
  - v4.0 경로에 정적 헤더를 보내면 `resultCode` 401 이다(공공망 실호출, 2026-11).
  - UAK 토큰을 `X-NHN-AUTHORIZATION` 으로 보내면 공공망 `instance list` 가 성공한다. `Bearer ` 접두사가 있어도 없어도 성공했다. [[adr-046]] 이 미확정으로 남긴 접두사는 문서의 「Bearer 유형 토큰」 에 맞춰 붙인다. 같은 헤더를 [[adr-027]] 의 API Gateway 도 `Bearer` 로 쓴다.
  - v4.0 으로 옮긴 뒤 `instance`, `schema`, `user`, `backup`, `storage`, `ha`, `binlog`, `parameter-group` 의 읽기 호출을 공공망에서 확인했다. 쓰기는 미리보기까지만 호출했고 반영 요청은 보내지 않았다. 따라서 쓰기 요청 본문과 응답(특히 빈 본문 응답)은 문서 기준이다.
  - 파라미터 그룹 목록에서 `dbVersion` 이 `null` 이고 `dbEngineVersionFamily` 만 있는 그룹이 실제로 있다. 그래서 `dbVersion` 을 선택 필드로 받는다.
  - 파라미터 그룹을 DB 인스턴스에 적용하는 유지 관리(목록·즉시 실행) 명령은 이 결정 범위 밖이다. 후속 변경에서 더한다.
- **대안 기각**:
  - 새 명령만 v4.0 으로 보내기: 한 명령군에 인증 방식이 두 갈래가 되고, 토큰 캐시와 정적 헤더 클라이언트를 함께 유지해야 한다.
  - v3.0 정적 헤더로 v4 전용 경로 호출: 실호출에서 401 이다.
  - 응답 본문 없는 쓰기에 `--wait`: 기다릴 작업 ID 가 없다. 대신 조회 명령으로 반영을 확인한다.
  - 파라미터 값 변경 때 DB 인스턴스에 바로 적용: 적용 API 가 유지 관리 쪽에 있고 재시작을 부를 수 있어 한 명령에 섞지 않는다.
- **결과**:
  - 얻는 것: 콘솔에서만 하던 바이너리 로그 정리, 스토리지 확장, 파라미터 그룹 변경, 고가용성 복구를 같은 쓰기 안전 규칙(`--yes` 없으면 미리보기)으로 한다.
  - 감당할 것: 토큰 발급 호출이 첫 요청에 붙는다(캐시 후 재사용). 반영 요청의 응답 형식은 실호출로 확인하지 않았고, 다르면 클라이언트 한 곳만 고친다. `FILE` 적용 유형의 재시작 의미는 추정이다.
- **적용 범위**: `rds-mysql` 명령군 전체. 엔드포인트 host 는 `src/api/endpoints.ts` 가 소유한다.
