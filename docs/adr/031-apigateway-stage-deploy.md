# ADR-031: API Gateway 스테이지 반영과 배포 — 비동기 배포 확인, 2단계 롤백, 응답 스키마 불일치 회피

- **결정**: 배포를 요청한 뒤 결과까지 CLI 가 확인하고, 롤백은 되돌리기까지만 하고 배포를 대신하지 않는다.
  - `deploy create` 는 기본으로 결과를 기다린다. `--no-wait` 로만 요청에서 끝낸다.
    다른 대기 명령이 `--wait` 로 켜는 것과 반대다.
  - 완료 판정은 호출 직전에 기록한 배포 ID 를 기준으로 삼는다.
    최근 배포 결과의 ID 가 달라지고, 그 상태가 `DEPLOYING` 을 벗어나야 끝낸다.
    두 조건을 함께 봐야 직전 배포의 결과를 이번 것으로 읽지 않는다.
    배포 이력이 없어 비교할 ID 가 없을 때만 상태 하나로 판정한다.
  - `FAILURE` 는 종료 코드로 드러낸다. 대기 상한을 넘기면 마지막 상태를 담아 실패로 끝낸다.
  - 롤백은 되돌리기만 수행하고, 적용에 배포가 필요하다는 안내를 낸다.
    되돌리기와 배포를 한 명령으로 묶지 않는다.
  - 반영과 롤백의 응답에서 `customBackendEndpointUrl` 을 출력하지 않는다.
- **맥락**: 배포 요청의 응답에는 배포 ID 도 상태도 없다. 본문이 공통 헤더뿐이다.
  - 문서는 "배포 결과가 업데이트되기까지 최대 1분 정도까지 소요될 수 있다" 고 적는다.
    그래서 200 은 접수만 뜻하고, 성공 여부는 최근 배포 결과 조회로 따로 확인해야 한다.
    자동화가 200 을 성공으로 읽으면 `FAILURE` 인 배포를 성공으로 오해한다.
    이 오해가 실제로 값비싼 쪽이라 기본을 대기로 둔다.
  - 응답이 배포 ID 를 주지 않으므로 어느 결과가 이번 호출의 것인지 확정할 방법이 없다.
    호출 직전 ID 를 기준으로 삼아도, 같은 스테이지에 동시에 배포하는 경합은 CLI 가 풀 수 없다.
  - 롤백은 "현재 스테이지 설정을 모두 삭제" 하고 되돌리지만 서비스에는 반영하지 않는다.
    되돌린 설정을 적용하려면 배포를 따로 해야 한다.
  - 변경 사항이 없으면 반영과 배포가 **둘 다 오류로 실패한다.**
    문서는 반영을 "수행되지 않습니다" 로 적어 아무 일도 없이 끝나는 것처럼 읽히지만,
    실측하면 `The latest resource has already been applied.` 가 온다.
    배포는 `Failed to deploy because stage is not changed.` 다.
    문서 서술만 믿고 반영을 no-op 으로 다루면, 응답 목록이 온다고 가정한 코드가 빈손으로 남는다.
  - 배포마다 새 배포 ID 레코드가 생긴다. 실측으로 확정했다.
    완료 판정이 이 전제 위에 있어, 서버가 최근 레코드의 상태만 바꾸는 구조였다면
    기본 경로가 매번 상한을 채우고 실패했을 것이다.
    실제 소요는 3초 남짓으로 문서가 말하는 상한(최대 1분)보다 짧다.
  - 롤백 응답 예시의 필드가 다른 조회 응답과 다르다.
    예시는 `customEndpointUrl` 인데 같은 문서의 필드 표는 `customBackendEndpointUrl` 로 적어 서로 어긋난다.
    문서로는 어느 쪽이 실제인지 확정할 수 없다.
- **대안 기각**:
  - 요청만 하고 끝내기 — 배포 성공과 접수를 구분할 수단이 사용자에게 남지 않는다.
    확인 명령을 따로 실행하게 하면 이슈 [#87](https://github.com/jon890/nhncloud-cli/issues/87) 에서 본
    "첫 응답을 잘못 읽고 헛도는" 경로가 그대로 재현된다.
  - 롤백에 배포를 이어 붙이기 — 두 호출 사이에 실패하면 되돌리기만 된 상태가 남는다.
    서버가 두 단계로 나눈 경계를 CLI 가 지운다.
  - 롤백 응답에 조회용 가드 재사용 — 필드 이름이 어긋나 성공 응답을 거부할 수 있다.
    [[adr-028]] 이 스테이지 수정에서 같은 이유로 쓰기 전용 가드를 택했다.
  - 출력에서 어긋난 필드를 두 이름으로 모두 받기 — 문서가 틀린 쪽을 고르면 빈 값이 조용히 나간다.
    출력하지 않으면 어느 쪽이 맞든 결과가 같다.
- **트레이드오프**: 대기가 기본이라 배포 한 번에 최대 1분이 걸린다.
  후처리를 이어 붙이는 자동화에서는 `--no-wait` 로 끌 수 있게 남긴다.
- **적용 범위**: 이 ADR 은 스테이지 반영과 배포·롤백에 한정한다.
  배포 이력 삭제와 스테이지 리소스 단건 수정은 다루지 않는다.
  후자는 플러그인을 모두 지우고 요청한 것만 다시 등록해,
  [[adr-028]] 이 리소스 플러그인에서 확인한 upsert 와 반대로 동작한다.
  같은 이름으로 묶으면 두 시맨틱이 섞이므로 별도 결정으로 남긴다.
