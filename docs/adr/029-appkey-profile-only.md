# ADR-029: appkey 는 profile 로만 지정한다 — 명령 단위 오버라이딩 제거

- **결정**: appkey 를 쓰는 명령에서 `--app-key` 오버라이딩을 없애고 profile 하나로만 해석한다.
  - `apigateway` 는 지금 제거한다. 이것도 게시된 옵션을 없애는 깨는 변경이다.
    다만 그 조회 명령은 직전 `v0.13.0` 에서 처음 나왔고, 그 사이 이 옵션을 쓴 스크립트가
    자리 잡을 시간이 없었다고 판단했다.
  - `deploy`·`ncr`·`ncs` 는 여러 버전에 걸쳐 게시되어 쓰이므로 major 버전에서 제거한다(이슈 #85).
  - 그때까지 네 서비스의 옵션 표면이 갈린 상태로 남는다.
- **맥락**: appkey 를 지정하는 경로가 둘이면 어느 값이 쓰였는지 명령 이력만 보고 알 수 없다.
  - profile 을 바꿔도 `--app-key` 가 박힌 스크립트는 계속 옛 appkey 를 쓴다.
    자격증명 회전이 조용히 누락되는 경로다.
  - 옵션 정의만 38곳이고 도움말·JSDoc·오류 메시지까지 더하면 44곳이다.
    같은 우선순위 서술이 그만큼 복제되어 있다.
  - appkey 는 자격증명 파일에 한 곳으로 모아야 감사와 회전이 단순해진다([[adr-004]]).
- **대안 기각**:
  - 네 서비스를 한 번에 제거 — 게시된 명령의 옵션을 없애면 기존 스크립트가
    `unknown option` 으로 실패한다.
    도입 직후라 영향이 좁은 `apigateway` 와 달리, 나머지 셋은 여러 버전에 걸쳐 쓰여 왔다.
  - `apigateway` 도 함께 미루기 — 이 PR 이 추가하는 쓰기 명령 3개까지
    같은 오버라이딩 표면을 달고 나가게 된다. 나중에 걷어낼 표면을 지금 늘리지 않는다.
  - 폐기 예고 후 유지 — 예고 출력을 넣는 것도 게시된 동작 변경이라
    major 를 기다려야 하는 제약이 같다. 단계를 늘려도 얻는 것이 없다.
  - 그대로 유지 — 두 경로가 남아 있는 동안 회전 누락 위험도 남는다.
- **트레이드오프**: 여러 appkey 를 번갈아 쓰는 사용법은 profile 을 나눠야 한다.
  한 번에 여러 프로젝트를 훑는 스크립트는 `--profile` 을 반복해 지정한다.
- **적용 범위**: 이 ADR 은 appkey 지정 경로에 한정한다.
  region 과 profile 자체의 옵션 우선순위는 바꾸지 않는다.
