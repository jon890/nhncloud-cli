# ADR-023: NCS workload 시간 필터를 UTC Z로 정규화

- **결정**: `workload logs`와 `workload events`의 `--from`·`--to`는 시간대 포함 RFC3339와 상대시간을 받는다.
  CLI는 두 값을 같은 기준 시각으로 계산해 UTC 초 단위 `Z` 형식으로 바꾼 뒤 NCS API에 전달한다.
  형식 오류와 역전 범위는 인증 전에 입력 오류로 종료한다.
- **맥락**: 공식 NCS 문서는 `events` 시간 쿼리의 형식을 명시하지 않는다.
  2026-07-27 조회 실측에서 쿼리 생략과 UTC `Z`는 성공했다.
  시간대 오프셋·유닉스 시각·상대시간 원문은 서버 내부 오류를 반환했다.
  같은 제약이 `logs`에도 적용됐다.
  `ky`는 시간대 오프셋의 `+`를 정상 인코딩하므로 URL 인코딩 문제는 아니다.
- **대안 기각**:
  - 입력을 그대로 전달하면 문서상 유효해 보이는 값이 서버 오류가 되어 AI 에이전트가 원인을 판정할 수 없다.
  - 시간 옵션을 제거하면 API가 제공하는 기간 조회 기능과 기존 CLI 호환성을 잃는다.
  - `events`만 고치면 같은 API 제약과 공개 상대시간 예시를 가진 `logs`가 계속 실패한다.
- **트레이드오프**: 시간대 없는 절대시간은 실행 환경마다 의미가 달라지므로 허용하지 않는다.
  두 옵션을 생략했을 때는 API 기본 기간을 보존하기 위해 쿼리를 추가하지 않는다.
