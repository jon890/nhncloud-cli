# ADR-054: RDS for MySQL 알림 그룹·사용자 그룹·이벤트 구독의 수정은 현재 값을 읽어 전체를 보내고, 알림이 가지 않는 설정은 경고한다

- **status**: `accepted`. [[adr-047]], [[adr-051]] 의 쓰기 안전 규칙을 보안 그룹, 사용자 그룹, 알림 그룹, 이벤트 구독, 파라미터 그룹 생성·삭제에 넓힌다.
- **결정**:
  - `db-security-group`(`list`, `get`, `create`, `update`, `delete`, `rule create`·`update`·`delete`), `user-group`, `notification-group`, `event-subscription`(각 `list`, `create`, `update`, `delete`, 사용자 그룹과 알림 그룹은 `get` 포함), `metric`(`list`, `statistics`), `event`(`list`, `codes`)를 새 그룹으로 두고 `parameter-group` 에 `create`, `delete` 를 더한다. 쓰기는 [[adr-047]] 의 미리보기를 따르고 `--yes` 가 없으면 요청하지 않는다. 작업(`jobId`)을 돌려주는 요청(보안 그룹 규칙)만 `--wait` 를 받는다.
  - 알림 그룹, 사용자 그룹, 이벤트 구독의 `update` 는 현재 값을 읽어 지정한 항목만 바꾸고, 응답 본문 없는 PUT 에 현재 값을 포함한 전체를 보낸다. 문서가 수정 본문의 기본값을 꺼짐·빈 목록으로 적어, 생략한 필드를 서버가 지울 수 있기 때문이다. 목록 필드는 `--add-*`, `--remove-*` 로 현재 목록에 더하고 뺀다. 같은 값을 더하면서 빼거나 없는 값을 빼면 요청 전에 종료 코드 3이다. 지정한 값이 이미 같으면 요청하지 않는다.
  - 보안 그룹 규칙 수정도 같은 이유로 지정하지 않은 항목을 현재 규칙에서 채워 보낸다.
  - 알림이 가지 않는 설정(비활성, 이메일과 SMS 모두 끔, 감시 대상 DB 인스턴스 없음, 알림 받을 사용자 그룹 없음)은 `get` 과 쓰기 미리보기에서 stderr 로 경고한다. 사용자 그룹 `delete` 는 그 그룹을 쓰는 알림 그룹과 이벤트 구독을 먼저 찾아 경고한다.
  - 감시 대상 DB 인스턴스, 사용자 그룹, 프로젝트 멤버, 이벤트 코드, 파라미터 그룹의 엔진 버전은 요청 전에 있는지 확인하고, 없으면 종료 코드 3이다. 같은 이름의 그룹이 있으면 만들기 전에 종료 코드 3이다.
  - 응답 본문 없는 삭제와 수정이 오류로 끝나면 목록이나 상세를 다시 읽어 반영 여부를 확인한다([[adr-052]]). 삭제는 목록 전체를 읽어 대상이 없을 때만 반영된 것으로 본다.
  - 지표와 이벤트 조회의 `--from`, `--to` 는 시간대가 있는 ISO 8601 만 받고, 요청에는 항상 `+09:00`(콜론 있음)으로 바꿔 보낸다. `--last <m|h|d>` 는 지금까지의 기간이다. 시작이 종료보다 늦으면 종료 코드 3이다.
  - 보안 그룹 규칙의 포트는 `3306`(특정 포트), `3306-3310`(범위), `db`(DB 수신 포트), `all`(전체) 중 하나이고 문서의 한도(3306 이상 65535 이하)를 요청 전에 검사한다. 모든 주소(`0.0.0.0/0`, `::/0`)에서 들어오는 규칙은 경고한다.
- **맥락**:
  - 실사용(2026-11-16)에서 real DB 의 알림 그룹이 dev 기본 그룹 하나뿐이고 감시 대상이 비어 있어 저장 공간 가득 참을 알리지 못했다. 알림 그룹, 사용자 그룹, 감시 설정을 CLI 로 보고 고칠 수 있어야 하고, 알림 그룹이 있어도 감시 대상이 비면 알림이 가지 않는다는 점을 미리 알려야 한다.
  - 지표 조회는 `from`, `to` 를 콜론 있는 시간대(`+09:00`)로 보내야 받는다. 콜론 없는 `+0900` 은 서버가 80400 으로 거절한다.
  - 보안 그룹, 사용자 그룹, 알림 그룹, 모니터링, 이벤트, 이벤트 구독, 파라미터 그룹 생성·삭제는 일반망과 공공망 v4.0 문서에 모두 있고 경로와 본문이 같다. 공공망에서 빠진 기능은 없고 region 만 `kr1` 로 제한된다.
  - 이 변경은 실호출 검증 없이 문서 기준이다. 요청 본문과 응답, 지표 조회의 `measureNames`(배열)를 쉼표로 이어 보내는 방식, 규칙 삭제의 `ruleIds`(쉼표로 이은 쿼리), 포트 유형별 `minPort`·`maxPort` 처리는 문서에 형식이 없어 확인하지 못했다. 규칙 `PORT` 유형은 `minPort` 와 `maxPort` 를 같은 값으로 보낸다.
  - 공식 문서: [API v4.0 가이드](https://docs.nhncloud.com/ko/Database/RDS%20for%20MySQL/ko/api-guide-v4.0/), [공공기관용 API v4.0 가이드](https://docs.gov-nhncloud.com/ko/Database/RDS%20for%20MySQL/ko/api-guide-v4.0-gov/).
- **대안 기각**:
  - 수정 요청에 지정한 항목만 보내기: 문서가 생략한 필드의 기본값을 꺼짐·빈 목록으로 적었다. 감시 대상이나 수신자가 조용히 지워지면 알림이 멈추는데 사용자는 모른다.
  - 목록을 통째로 바꾸는 옵션(`--instance` 로 교체)만 두기: 현재 목록을 먼저 읽지 않으면 하나를 더하려다 나머지를 지운다. 더하고 빼는 옵션이 안전하다.
  - 알림이 가지 않는 설정을 오류로 막기: 만드는 도중의 중간 상태이거나 일부러 끄는 경우가 있다. 막지 않고 경고한다.
  - `+0900` 을 그대로 서버에 보내기: 서버가 받지 못한다. 입력은 받아 주고 보낼 때 바꾼다.
- **결과**:
  - 얻는 것: 알림 그룹과 감시 설정을 콘솔 없이 같은 쓰기 안전 규칙으로 보고 고치며, 저장 공간 같은 지표 알림이 빠지는 설정을 미리 알아챈다.
  - 감당할 것: 전체를 다시 보내므로 읽기와 쓰기 사이에 다른 사람이 같은 그룹을 고치면 덮어쓴다. 쓰기 본문은 문서 기준이라 서버 동작이 다르면 클라이언트 한 곳만 고친다. 사용자 그룹을 쓰는 알림 그룹을 찾으려고 알림 그룹 상세를 하나씩 읽어 삭제 미리보기가 느리다.
- **적용 범위**: `rds-mysql` 의 `db-security-group`, `user-group`, `notification-group`, `metric`, `event`, `event-subscription` 명령과 `parameter-group create`·`delete`. 엔드포인트와 인증은 [[adr-051]] 을 따른다.
