# ADR-036: Log & Crash 조회 토큰 사전 확인과 추정 대기 시간

- **결정**: 공식 Search v3 `available-token`을 명령으로 노출하고 `search`와 `export`의 각 검색 요청 직전에 잔량을 확인한다.
  - 잔량이 0 이하면 검색 요청을 보내지 않고 API 오류로 끝낸다.
  - 양수가 될 때까지의 추정 대기 시간은 `ceil((1 - availableToken) / 1.6)`초로 계산하고, 관측값에 따른 추정치임을 함께 알린다.
  - 잔량 조회 자체가 실패하면 검색 요청을 보내지 않고 원래 오류를 전달한다.
  - 자동으로 기다리거나 다시 시도하지 않는다.
    실제 요청이 429를 반환하면 [[adr-032]]의 즉시 실패와 부분 결과 보존을 유지한다.
- **맥락**: [Search v3 공개 명세](https://api-lncs-search.alpha-nhncloudservice.com/v3/lncs-api-gateway/openapi-public.yaml)는
  `GET /v3/{appkey}/logs/available-token`과 정수 `availableToken` 응답을 정의한다.
  [공식 API 가이드](https://docs.nhncloud.com/ko/Data%20&%20Analytics/Log%20&%20Crash%20Search/ko/api-guide/)는
  검색 기간, 크기와 쿼리 복잡도에 따라 토큰이 차감되고 시간이 지나면 보충된다고 설명하지만 회복 속도와 호출 비용은 보장하지 않는다.
  - 2026년 8월 31일 실측에서는 10초마다 16, 60초마다 100이 회복됐다.
    한 번의 선택적 24시간 조회에서는 약 21,870이 차감돼 성공 호출 뒤 잔량이 음수가 될 수 있었다.
  - 거부된 호출이 토큰을 차감한다는 초기 해석은 철회했다.
    음수 잔량은 직전 성공 호출의 큰 차감과 그 뒤 회복량만으로 설명된다.
  - 따라서 잔량이 양수라는 사실은 임의 검색 비용까지 충분하다는 뜻이 아니다.
    0 이하인 상태에서 결과 없는 요청을 보내지 않는 조건과 다음 시도 시점을 가늠하는 정보로만 쓸 수 있다.
- **대안 기각**:
  - 고정 간격 재시도 — 호출 비용이 관측마다 달라 짧은 간격은 아직 음수인 동안 같은 실패만 반복하고, 긴 간격은 프로세스를 불필요하게 붙잡는다.
  - 추정 시간이 끝날 때까지 자동 대기 — 1.6은 서버 계약이 아니고 다른 소비자가 같은 프로젝트 잔량을 바꿀 수 있어 성공 시점을 보장하지 못한다.
  - 양수 잔량을 예상 호출 비용과 비교 — 호출 비용을 요청 전에 계산할 공식 규칙이 없다.
  - 잔량 조회 실패 뒤 검색 강행 — 사전 조건을 확인하지 못한 상태에서 비용이 큰 검색을 보내므로 차단 목적을 무너뜨린다.
- **트레이드오프**: 각 검색 요청 앞에 조회 한 번이 추가된다.
  `available-token`이 일시적으로 실패하면 검색도 실패하며, 관측 속도가 바뀌거나 다른 소비자가 토큰을 쓰면 추정 시간이 어긋날 수 있다.
  대신 자동 대기 없이 stdout과 stderr, 종료 코드를 결정적으로 유지한다.
- **적용 범위**: `logncrash available-token`, `search`와 `export`의 검색 전 확인에 한정한다.
  500의 원인 판정과 적응형 기간 분할은 [[adr-030]], 실제 429와 부분 결과 보존은 [[adr-032]]가 계속 소유한다.
