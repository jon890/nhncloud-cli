**증상**: 이중 처리, 중복 안내나 불완전한 출력을 막는 조건문을 추가했지만 그 조건문을 제거해도 테스트가 모두 통과한다. 가드가 우연한 부작용에 기대면 주변 타입이나 반환값을 정리하는 변경이 숨은 계약을 깨뜨릴 수 있다.

**Good**: 가드를 추가할 때 가드가 없으면 실패하는 회귀 테스트를 함께 쓴다. 가능하면 조건문을 잠시 제거하거나 반대로 바꾸는 변이 검증으로 테스트가 실제로 실패하는지 확인한다. 재현할 테스트를 만들 수 없다면 가드가 필요한지, 더 명시적인 구조로 바꿀 수 있는지 다시 판단한다.

**검출**:

```bash
git diff -- src/ test/ tests/
rg -n "if \(|guard|already|closed|duplicate" src/
```

가드와 함께 바뀐 테스트가 있는지 대조하고, 대상 가드를 제거했을 때 그 테스트가 실패하는지 확인한다.

**Self-check**: 이번에 추가하거나 유지한 가드는 어떤 실패를 막는가? 그 가드만 제거하면 실패하는 테스트가 있는가? 가드가 막는 계약을 주석이나 타입으로 더 분명히 표현했는가?

**Why**: plan063 검토에서 JSON 배열의 이중 닫기와 안내 문구의 중복을 막는 가드를 제거해도 전체 테스트가 통과했다. 정상 경로 테스트만으로는 가드의 필요성을 입증할 수 없으므로 변이 검증이 필요하다.
